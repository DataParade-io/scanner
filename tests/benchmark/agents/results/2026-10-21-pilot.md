## Setup and what is fragile

- Pi 0.73.1 (`npm install -g @mariozechner/pi-coding-agent`). GPT-6 Luna is not in Pi's built-in list, so it is added in `~/.pi/agent/models.json` under the `openai` provider: id `gpt-6-luna`, api `openai-responses`, `apiKey: "OPENAI_API_KEY"` (the variable name; Pi reads the value from the environment). Model id confirmed from `GET /v1/models`; `gpt-5.6-luna` also exists and was not used.
- Invocation: `pi --offline --model openai/gpt-6-luna --thinking low --mode json --no-session --no-context-files --no-extensions --no-skills --no-prompt-templates -p <assignment>` with stdin closed. Without `--offline` and a closed stdin a first probe hung with no output.
- Tokens: each assistant `message_end` event in `--mode json` carries `usage {input, output, cacheRead, cacheWrite, cost}` per model request; `input` is the uncached part, cached input is `cacheRead`. The harness sums these and prices them from `prices.json` (long-context tier per request). Pi's own cost is a cross-check; no mismatch was flagged.
- Gold flow labels are not self-flows (subject keys are like `flow:pii-model->database` and `flow:pii->checkr-api`), but their `flow_canonical` endpoints repeat the same kind on both sides (`asset:database->asset:database`). Flows are therefore matched on the target's `type:subType` plus evidence; the source side carries no usable information in the gold.
- Matching is one-to-one, so an agent that reports the same destination at many call sites is penalised for duplicates (vgs-django flows) and a model that reports one item per file cannot score above the number of gold labels.
- Evidence strictness changes the scanner a lot: on vgs-django the scanner scores 50%/50% (components) within 10 lines and 0%/0% on strict overlap, because its spans are a few lines off the gold spans.
- The discourse agent run is low quality but real: Luna made 6 requests and 8 tool calls, then wrote 222 components and 58 flows, almost all one-line spans on model-file headers (`startLine: 3`) with no read of the code. Only 2 of 222 landed near a gold label. This is a model and prompt effect (it did not read the files), not a harness fault, but a single run at low thinking says little about the model.
- Scanner flow precision on discourse is very low (373 in-scope flows, 7 correct) while recall is 44%; the gold flow count is small relative to what the scanner emits, so precision there mostly measures how much the scanner emits beyond the labelled flows.
- The two packets have different scopes: gold covers only the reviewed scope files, and precision ignores items outside them. Discourse scans `app/models/` and `config/`, the sparse checkout.
- Scanner wall time on discourse is 100s; the agent took 24s.
- Vocabulary (`vocabulary.json`) is interim: types from scanner unions, subTypes from gold. DATAP-740 replaces it.
- Total spend for this rerun: about $0.006 (two Pi runs).
